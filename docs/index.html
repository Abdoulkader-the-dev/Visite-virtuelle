Documentation technique

Visite virtuelle 360° avec transitions blink et mode VR WebXR.

🚀 Quick start — Ajouter un panorama

Ouvrez js/config.js. Copiez un bloc de scène existant (par exemple '12'), changez l'identifiant, le name, le chemin image (qui doit pointer vers ./images/processed/ après traitement), ajustez defaultBearing et defaultLat si nécessaire, et définissez les hotspots. C'est tout – le menu, la minimap et la navigation VR s'adaptent automatiquement.

Images supportées : .webp (recommandé), .jpg, .jpeg, .JPG. Le chargeur essaie plusieurs extensions.

Nouveau : un script de traitement d’images (tools/process-images.js) permet de redimensionner et convertir automatiquement toutes les images en WebP, et les place dans images/processed/.

💡 Conseil : utilisez hotspot-editor.html pour capturer les coordonnées des hotspots visuellement.

📌 Aperçu du projet

Ce projet est un visiteur virtuel 360° qui affiche des panoramas équirectangulaires. L'utilisateur navigue en cliquant sur des hotspots (cercles pulsants) qui déclenchent une transition instantanée (blink) vers une autre scène. La vue est contrôlée à la souris et le mode VR est entièrement fonctionnel avec les contrôleurs Meta Quest.

Technologies : Three.js (r128), GSAP, WebXR. Toute la configuration est centralisée dans config.js.

🖼️ Affichage et traitement des images

Les panoramas sont des images équirectangulaires (format 2:1). Elles sont projetées sur une sphère de rayon 500.

Code de la sphère (main.js)

function createSphere() {
    var geo = new THREE.SphereGeometry(500, 60, 40);
    geo.scale(-1, 1, 1);                      // normales inversées → vue de l'intérieur
    var mat = new THREE.MeshBasicMaterial({
        color: 0xffffff,
        side: THREE.DoubleSide,
        transparent: true,
        opacity: 1,
        depthWrite: true
    });
    return new THREE.Mesh(geo, mat);
}

Traitement automatique des images (tools/process-images.js)

Un script Node.js (avec la bibliothèque sharp) redimensionne toutes les images du dossier images/ à une taille maximale de 4096×2048 (sans agrandissement), les convertit en WebP (qualité 80) et les place dans images/processed/. Les fichiers originaux sont supprimés pour ne pas alourdir le projet. 

// extrait de process-images.js
const IMAGE_DIR = path.join(__dirname, '..', 'images');
const PROCESSED_DIR = path.join(__dirname, '..', 'images', 'processed');
const MAX_WIDTH = 4096;
const MAX_HEIGHT = 2048;
const QUALITY = 80;

sharp(inputPath)
    .resize(MAX_WIDTH, MAX_HEIGHT, { fit: 'inside', withoutEnlargement: true })
    .webp({ quality: QUALITY })
    .toFile(outputPath)
    .then(() => fs.unlinkSync(inputPath));
💡 Lancez npm install dans le dossier tools/ puis npm start pour traiter toutes les images.

Pourquoi la caméra doit rester en (0,0,0)

La sphère est centrée à l'origine. La caméra est en (0, 0, 0.001). Ne jamais modifier la hauteur (Y) de la caméra en VR – l'image serait déformée. L'alignement de l'horizon se fait via defaultLat qui tourne la sphère sur l'axe X. 

var defaultLat = sceneConfig.defaultLat || 0;
window.tourState.sphere.rotation.x = -defaultLat * Math.PI / 180;

🧩 Composants 3D

La scène Three.js contient plusieurs groupes dynamiques.

1. La sphère principale

main.js – createSphere()

2. Les hotspots (cercles pulsants) – createPulseCircles()

  • En 2D : rouges (0xFF0000), rayon 0.25.
  • En VR : bleus (0x1E90FF), rayon 0.5.
  • La reconstruction est automatique à l’entrée/sortie de la session VR via rebuildHotspots(). 
var isVR = window.tourState.isXRActive;
var radius = isVR ? 0.5 : 0.25;
var color = isVR ? 0x1E90FF : 0xFF0000;

La texture utilisée est neutre (blanc/gris) pour que material.color la teinte correctement.

3. Le HUD VR (bouton Quitter VR) – buildVRUI()

  • Distance : 0.5 m (PANEL_DISTANCE = 0.5).
  • Texte orienté correctement (pas de miroir).
  • Position : légèrement en haut (y = 0.4), centré horizontalement.

4. La flèche au sol

Elle est masquée en VR car elle n’est pas utile (le laser sert à pointer).

🖱️ Vue 2D

La caméra est définie par lon, lat et fov.

function updateCameraLookAt() {
    var phi   = (90 - lat) * Math.PI / 180;
    var theta = lon * Math.PI / 180;
    camera.lookAt(
        500 * Math.sin(phi) * Math.cos(theta),
        500 * Math.cos(phi),
        500 * Math.sin(phi) * Math.sin(theta)
    );
    if (camera.fov !== fov) {
        camera.fov = fov;
        camera.updateProjectionMatrix();
    }
}
  • Glisser : modifier lon et lat.
  • Molette : modifier fov (zoom).
  • Flèches clavier : rotation et inclinaison.
  • + / - : zoom.
  • F : plein écran.
  • Backspace : retour arrière.
  • Échap : fermer la fiche info.

Après 5 secondes d'inactivité, la vue tourne automatiquement.

⏳ Transitions (blink)

Les transitions sont instantanées : fondu au noir de 150 ms, changement de sphère et de lon/lat, puis fondu enchaîné. Cette approche évite le mal des transports en VR. 

// extrait de transition.js – triggerGSVTransition
overlay.style.transition = 'opacity 0.15s ease';
overlay.style.opacity = '1';

var texturePromise = loadTextureAsync(sceneConfig.image);

setTimeout(function () {
    texturePromise.then(function (tex) {
        var newSphere = window.createSphere();
        newSphere.material.map = tex;
        newSphere.material.needsUpdate = true;
        var defaultLat = sceneConfig.defaultLat || 0;
        newSphere.rotation.x = -defaultLat * Math.PI / 180;

        var parentGroup = vrGroup || scene;
        parentGroup.add(newSphere);
        if (oldSphere) {
            parentGroup.remove(oldSphere);
            oldSphere.geometry.dispose();
            oldSphere.material.dispose();
        }
        window.tourState.sphere = newSphere;
        window.tourState.currentTexture = tex;

        window.tourState.lon = arrivalTargetLon;
        window.tourState.lat = arrivalTargetLat;
        camera.position.set(0, 0, 0.001);
        window.tourState.fov = 75;
        camera.fov = 75;
        camera.updateProjectionMatrix();

        window.tourState.currentScene = targetSceneId;
        updateSceneUi();

        overlay.style.opacity = '0';
        window.tourState.isTransitioning = false;
        window.tourState.controlsEnabled = true;
    });
}, 150);
💡 Pourquoi instantané ? En VR, les mouvements prolongés provoquent des nausées. Le blink est confortable et fiable.

📍 Hotspots (2D)

Le raycasting depuis la souris détecte les hotspots.

var ndc = new THREE.Vector2(
    (event.clientX / window.innerWidth) * 2 - 1,
    -(event.clientY / window.innerHeight) * 2 + 1
);
raycaster.setFromCamera(ndc, camera);
var intersections = raycaster.intersectObject(sphere);
if (intersections.length) {
    var point = intersections[0].point.clone();
    var lat = Math.asin(point.y / 500) * 180 / Math.PI;
    mouseSphereLat = lat;
    mouseSpherePoint = point;
}

Le clic sur un hotspot déclenche triggerGSVTransition().

🥽 Mode VR

Le mode VR utilise WebXR (immersive-vr). Il est compatible avec les contrôleurs Meta Quest.

1. Gestion de session

À chaque entrée en VR, les hotspots sont recréés avec les bonnes couleurs et tailles via rebuildHotspots(). La sortie restore le mode 2D. 

function onXRSessionStart() {
    // ...
    if (window.rebuildHotspots) {
        window.rebuildHotspots();   // ← crucial pour passer en bleu/taille 0.5
    }
    // ...
}

function onXRSessionEnd() {
    // ...
    if (window.rebuildHotspots) {
        window.rebuildHotspots();   // ← retour au rouge/taille 0.25
    }
    // ...
}

2. Contrôleurs et lasers

Les contrôleurs sont créés immédiatement (setupXRControllers()). Les lasers sont des lignes bleues (xr-laser.js) qui servent à pointer.

3. Hotspots en VR

  • Couleur : bleu ciel (#1E90FF).
  • Taille : 0.5 (double de la 2D).
  • Pas de survol (pour simplifier l’interaction).

4. HUD VR

  • Bouton "Quitter VR" à 0.5 m de distance.
  • Position : en haut (y = 0.4), centré horizontalement.
  • Le texte est lisible (pas de miroir).

5. Nettoyage

À la sortie de VR, tous les tweens GSAP sont tués, les contrôleurs retirés et le cache nettoyé pour permettre une ré‑entrée sans rechargement.

⚡ Performance & cache

Le cache LRU stocke jusqu’à 50 textures. Les images sont chargées une seule fois.

Le traitement des images (redimensionnement, conversion WebP) réduit considérablement le poids des fichiers et améliore les temps de chargement, notamment en VR.

➕ Ajouter une scène

  1. Ouvrir js/config.js.
  2. Copier un bloc existant et changer l’ID (ex: '36').
  3. Modifier name, image (chemin vers ./images/processed/), defaultBearing, defaultLat, minimapX/Y et les hotspots.
  4. Placer l’image dans images/ puis lancer le script de traitement (npm start dans tools/).
  5. Rafraîchir la page – la scène apparaît automatiquement.
💡 L’image doit être dans images/processed/ pour être utilisée par le site.

🎯 Ajouter / modifier un hotspot

Deux méthodes :

Méthode 1 : Éditeur visuel (hotspot-editor.html)

  1. Ouvrir hotspot-editor.html dans le navigateur.
  2. Naviguer (clic‑glisser) jusqu’à l’endroit voulu.
  3. Cliquer sur l’image pour capturer les coordonnées {x, y, z}.
  4. Remplir les champs (type, target, bearing, label, etc.).
  5. Cliquer sur « Copier hotspot complet ».
  6. Coller le code dans config.js.

Méthode 2 : Édition manuelle

💡 bearing et arrivalLon sont indépendants. L’éditeur vous aide à les régler précisément.

⚠️ Limites importantes

  • Hauteur de la caméra – ne pas modifier camera.position.y.
  • Centre de la sphère – ne pas la déplacer.
  • Durée de transition – ne pas dépasser 150 ms (risque de nausée).
  • Nettoyage VR – ne pas supprimer clearXRControllers() et destroyVRUI().
  • Cache LRU – ne pas désactiver (50 textures est un bon compromis).
  • Traitement des images – toujours passer par le script pour éviter des fichiers trop lourds.
⚠️ Toute modification dans ces zones cassera l’expérience VR ou provoquera des fuites mémoire.
