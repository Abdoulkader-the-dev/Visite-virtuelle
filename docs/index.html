Documentation technique

Visite virtuelle 360° avec transitions style Google Street View et mode VR.

🚀 Quick start — Ajouter un panorama

Ouvrez js/config.js. Copiez un bloc de scène existant (par exemple '12'), changez l'identifiant, le name, le chemin image, ajustez defaultBearing et defaultLat si nécessaire, et définissez les hotspots. C'est tout – le menu, la minimap et la navigation VR s'adaptent automatiquement.

Image supportée : .webp, .jpg, .jpeg, .JPG. Le chargeur essaie plusieurs extensions.

💡 Conseil : utilisez hotspot-editor.html pour capturer les coordonnées des hotspots visuellement.

📌 Aperçu du projet

Ce projet est un visiteur virtuel 360° qui affiche des panoramas équirectangulaires. L'utilisateur peut naviguer en cliquant sur des hotspots (cercles rouges pulsants) qui déclenchent une transition vers une autre scène. La vue est contrôlée à la souris (glisser pour tourner, molette pour zoomer) et le mode VR est entièrement fonctionnel avec les contrôleurs Meta Quest.

Technologies : Three.js (r128), GSAP (pour les animations), WebXR (immersive-vr). Toute la logique métier est dans js/ et la configuration est centralisée dans config.js.

🖼️ Affichage des images

Les panoramas sont des images équirectangulaires (format 2:1). Elles sont projetées sur une sphère de rayon 500.

Code de la sphère (main.js)

function createSphere() {
    var geo = new THREE.SphereGeometry(500, 60, 40);
    geo.scale(-1, 1, 1);                      // normales inversées → image vue de l'intérieur
    var mat = new THREE.MeshBasicMaterial({
        color: 0xffffff,
        side: THREE.DoubleSide,
        transparent: true,
        opacity: 1,
        depthWrite: true
    });
    return new THREE.Mesh(geo, mat);
}

Pourquoi la caméra doit rester en (0,0,0)

La sphère est centrée à l'origine. La caméra est placée en (0, 0, 0.001) (léger décalage pour éviter les artéfacts de profondeur). Ne jamais modifier la hauteur (Y) de la caméra en VR – l'image serait déformée (effet « insecte »). L'alignement de l'horizon se fait via defaultLat qui tourne la sphère sur l'axe X.

Alignement de l'horizon (defaultLat)

Dans loadScene() (main.js) : 

var defaultLat = sceneConfig.defaultLat || 0;
window.tourState.sphere.rotation.x = -defaultLat * Math.PI / 180;

Une valeur positive de defaultLat fait pivoter la sphère vers le bas, ce qui remonte l'horizon dans le champ de vision.

🧩 Composants 3D

La scène Three.js contient plusieurs groupes et objets qui sont créés dynamiquement à chaque changement de scène.

1. La sphère principale

main.js – createSphere()
Une seule sphère est active à la fois. Pendant une transition, une seconde sphère est créée puis l'ancienne est remplacée.

2. Le groupe des hotspots au sol

hotspots.js – createGroundHotspot()
Un groupe groundHotspotGroup contient l'anneau blanc et la flèche directionnelle. L'anneau est un RingGeometry et la flèche un ShapeGeometry. 

var ringGeo = new THREE.RingGeometry(0.12, 0.36, 64);
ringGeo.rotateX(-Math.PI / 2);
var hotspotMesh = new THREE.Mesh(ringGeo, ringMat);
hotspotMesh.position.set(0, GROUND_Y, 0);

3. Les cercles pulsants (hotspots interactifs)

hotspots.js – createPulseCircles()
Chaque hotspot de transition génère un disque rouge pulsant (rayon 0.5). Ces disques sont interactifs – ils sont ajoutés à allGroundHotspotMeshes et sont donc détectés par le raycaster. 

var geo = new THREE.PlaneGeometry(PULSE_CIRCLE_RADIUS * 2, PULSE_CIRCLE_RADIUS * 2);
geo.rotateX(-Math.PI / 2);
var mesh = new THREE.Mesh(geo, mat);
mesh.userData.hotspot = hotspot;
allGroundHotspotMeshes.push(mesh);

4. La flèche directionnelle (sol)

hotspots.js – createGroundHotspot()
Une flèche SVG est dessinée via un Shape et transformée en géométrie 3D. Elle suit le curseur ou le laser VR.

5. Le HUD VR (bouton Quitter VR)

vr-ui.js – buildVRUI()
Un panneau 3D (plane geometry) avec un texte dessiné sur canvas est placé à 3 mètres devant la caméra. Il est interactif via le laser.

⚙️ Configuration (config.js)

Toute la configuration est centralisée dans l'objet window.TOUR_CONFIG. Voici sa structure :

Propriétés d'une scène

name string
Nom affiché dans le menu et la minimap.
image string
Chemin vers l'image (webp, jpg, jpeg, JPG).
defaultBearing number
Direction de vue au chargement initial (0–359°). 0 = Nord.
defaultLat number
Rotation verticale de la sphère (degrés) pour aligner l'horizon.
minimapX number
Position X sur la minimap (0–100).
minimapY number
Position Y sur la minimap (0–100).
hotspots array
Liste des hotspots de la scène (transition ou info).

Propriétés d'un hotspot

position {x,y,z}
Coordonnées 3D sur la sphère.
x : gauche(−) / droite(+)
y : bas(−) / haut(+)
z : devant(−) / derrière(+) → −250 = devant
type 'transition' | 'info'
Transition = déplacement vers une autre scène.
Info = affiche une fiche d'information.
target string (ID)
ID de la scène cible (pour les transitions).
bearing number
Direction vers laquelle la caméra avance pendant la transition (0–359°).
arrivalLon number (optionnel)
Direction de vue après la transition. Si absent, calcul automatique (opposé du bearing).
arrivalLat number (optionnel)
Verticalité après la transition (défaut = 0).
label string
Texte affiché dans le tooltip (survol).
icon string (optionnel)
Emoji pour les hotspots info (ex: '💡').
title string (optionnel)
Titre de la fiche info.
description string (optionnel)
Description de la fiche info.

Exemple complet (scène '12' – Entrée)

'12': {
    name: 'Entrée',

            type: 'transition',

}
💡 Remarque : bearing et arrivalLon sont indépendants. bearing est la direction vers laquelle la caméra "avance" pendant la transition. arrivalLon est la direction finale après la transition (peut être différente).

🖱️ Vue 2D (contrôles souris)

La caméra est définie par trois variables : lon (longitude), lat (latitude) et fov (field of view).

Mise à jour de la caméra (main.js – updateCameraLookAt)

function updateCameraLookAt() {
    var phi   = (90 - lat) * Math.PI / 180;
    var theta = lon * Math.PI / 180;
    camera.lookAt(
        500 * Math.sin(phi) * Math.cos(theta),
        500 * Math.cos(phi),
        500 * Math.sin(phi) * Math.sin(theta)
    );
    if (camera.fov !== fov) {
        camera.fov = fov;
        camera.updateProjectionMatrix();
    }
}

Contrôles (controls.js)

  • Glisser : modifier lon et lat.
  • Molette : modifier fov (zoom).
  • Flèches clavier : rotation et inclinaison.
  • + / - : zoom.
  • F : plein écran.
  • Backspace : retour arrière.
  • Échap : fermer la fiche info.

Rotation automatique (main.js – updateAutoRotation)

Après 5 secondes d'inactivité (pas de glisser, pas de clic), la vue tourne automatiquement (lon += 0.03 par frame). Dès que l'utilisateur interagit, la rotation s'arrête. 

function updateAutoRotation() {
    if (Date.now() - lastInteractionTime > 5000 &&
        !isTransitioning && !isDragging) {
        lon += 0.03;
        autoRotating = true;
    }
}

defaultBearing et defaultLat

Au chargement initial d'une scène, loadScene() applique defaultBearing à lon et defaultLat à la rotation de la sphère. Cela permet de cadrer parfaitement chaque panorama.

⏳ Transitions

Les transitions sont instantanées (blink) : un fondu au noir de 150 ms, changement de sphère et de lon/lat, puis fondu enchaîné. Cette approche évite le mal des transports en VR et assure une expérience fluide.

Code clé (transition.js – triggerGSVTransition)

// 1. Fade to black (0.15s)
overlay.style.transition = 'opacity 0.15s ease';
overlay.style.opacity = '1';

// 2. Charger la nouvelle texture
var texturePromise = loadTextureAsync(sceneConfig.image);

// 3. Après 150 ms, attendre la texture puis basculer
setTimeout(function () {
    texturePromise.then(function (tex) {
        // Créer la nouvelle sphère
        var newSphere = window.createSphere();
        newSphere.material.map = tex;
        newSphere.material.needsUpdate = true;
        // Appliquer defaultLat
        var defaultLat = sceneConfig.defaultLat || 0;
        newSphere.rotation.x = -defaultLat * Math.PI / 180;

        // Remplacer l'ancienne sphère
        scene.add(newSphere);
        scene.remove(oldSphere);
        window.tourState.sphere = newSphere;

        // Appliquer lon/lat
        window.tourState.lon = arrivalTargetLon;
        window.tourState.lat = arrivalTargetLat;
        camera.position.set(0, 0, 0.001);

        // Fade back in
        overlay.style.opacity = '0';
    });
}, 150);
💡 Pourquoi instantané ? En VR, les mouvements prolongés (dolly, flou) provoquent des nausées. Le blink est confortable et fiable.

📍 Hotspots (2D)

En 2D, le clic sur un hotspot est détecté par raycasting depuis la souris vers la sphère, puis projection sur le plan du sol.

1. Raycaster et intersection avec la sphère (controls.js – trackMouseOnSphere)

    (event.clientX / window.innerWidth) * 2 - 1,
    -(event.clientY / window.innerHeight) * 2 + 1
);
raycaster.setFromCamera(ndc, camera);
var intersections = raycaster.intersectObject(sphere);
if (intersections.length) {
    var point = intersections[0].point.clone();
    var lat = Math.asin(point.y / 500) * 180 / Math.PI;
    mouseSphereLat = lat;
    mouseSpherePoint = point;
}

2. Projection sur le plan du sol (hotspots.js – updateMouseArrow)

var groundPlane = new THREE.Plane(new THREE.Vector3(0, 1, 0), -GROUND_Y);
groundRaycaster.ray.intersectPlane(groundPlane, groundPoint);

3. Recherche du hotspot le plus proche (hotspots.js – nearestTransitionHotspot)

function nearestTransitionHotspot(point) {
    var hotspots = transitionHotspots();
    var nearest = null;
    var nearestDistance = Infinity;
    hotspots.forEach(function (hotspot) {
        var distance = hotspot.positionVector.distanceToSquared(point);
        if (distance < nearestDistance) {
            nearestDistance = distance;
            nearest = hotspot;
        }
    });
    return nearest;
}

4. Aimantation de la flèche (effet « Street View »)

La flèche au sol se positionne à l'intersection du raycaster avec le sol, puis s'aligne sur le hotspot le plus proche. Elle sert d'indicateur visuel avant le clic.

5. Clic → transition

controls.js – endPointer() vérifie que le déplacement de la souris est inférieur à 5 pixels (pas de drag), puis appelle onValidClick() (hotspots.js) qui déclenche triggerGSVTransition().

⚡ Performance & cache des textures

Pour éviter de recharger les images à chaque transition, le projet utilise un cache LRU (Least Recently Used) avec une capacité de 50 textures (MAX_CACHED_TEXTURES = 50).

Fonctionnement du cache (main.js – loadTexture)

if (textureCache.has(path)) {
    // Texture déjà chargée → la remonter en tête de cache
    var cached = textureCache.get(path);
    textureCache.delete(path);
    textureCache.set(path, cached);
    return Promise.resolve(cached);
}
// Sinon, charger depuis le disque
textureLoader.load(candidate, function(texture) {
    textureCache.set(path, texture);
    evictLRUIfNeeded(); // Supprime la texture la moins utilisée si la limite est atteinte
    resolve(texture);
});

Éviction LRU (main.js – evictLRUIfNeeded)

Si le cache dépasse 50 entrées, la fonction supprime les textures qui ne sont pas utilisées par la scène courante (isTextureInUse()) et qui sont les plus anciennes. 

function evictLRUIfNeeded() {
    if (textureCache.size <= MAX_CACHED_TEXTURES) return;
    var it = textureCache.keys();
    for (var key of it) {
        if (textureCache.size <= MAX_CACHED_TEXTURES) break;
        var texture = textureCache.get(key);
        if (!isTextureInUse(texture)) {
            texture.dispose();
            textureCache.delete(key);
        }
    }
}
💡 Pourquoi 50 ? Le projet contient 24 scènes ; 50 est une marge confortable. Si vous ajoutez beaucoup de scènes, vous pouvez augmenter cette valeur, mais attention à la mémoire du navigateur.

⚠️ Limites importantes

Certains aspects du code sont critiques et ne doivent jamais être modifiés sans comprendre les conséquences :

  • Hauteur de la caméra – la caméra doit rester en (0, 0, 0.001). Modifier Y déforme l'image en VR (effet « insecte »).
  • Centre de la sphère – la sphère est centrée à l'origine. Ne pas la déplacer.
  • Durée de transition (150 ms) – ne pas augmenter la durée du fondu au noir en VR (risque de nausée).
  • Nettoyage des contrôleurs VR – ne pas supprimer clearXRControllers() et destroyVRUI() dans onXRSessionEnd() – ils sont essentiels pour la ré‑entrée en VR sans rechargement.
  • Rotation de la sphère pour defaultLat – ne pas tenter d'ajuster la hauteur de la caméra à la place ; utilisez defaultLat pour chaque scène.
  • Cache textures (LRU) – ne pas désactiver le cache sans comprendre l'impact mémoire. La limite de 50 textures est un bon compromis.
⚠️ Ces règles sont indispensables – toute modification dans ces zones cassera l'expérience VR ou provoquera des fuites mémoire.
